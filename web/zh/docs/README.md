# G-Tunnel 文档

G-Tunnel(`gt`)是一个高性能中转代理:在公网中转服务器与内网服务旁的客户端之间,以 WebSocket(s)/HTTP(s)/TCP 承载你的流量。Rust 异步数据面搭配 Go 控制面,高负载下依然稳定——wrk 实测吞吐最高达 frp 的 6 倍,满并发零错误。

所有内容都基于同一个 `gt` 二进制;`gt server` 与 `gt client` 只是启动不同角色。

## 工作原理

访问者到达公网中转,中转按主机名前缀或 TCP 端口识别目标,把流量交给发布该服务的客户端,客户端再转发给真正的本地服务:

```text
      ┌──────────────────────────────────────┐
      │  Web    Android     iOS    PC    ... │
      └──────────────────┬───────────────────┘
                  ┌──────┴──────┐
                  │  GT Server  │   公网中转
                  └──────┬──────┘
       ┌─────────────────┼─────────────────┐
┌──────┴──────┐   ┌──────┴──────┐   ┌──────┴──────┐
│  GT Client  │   │  GT Client  │   │  GT Client  │ ...
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
┌──────┴──────┐   ┌──────┴──────┐   ┌──────┴──────┐
│     SSH     │   │   HTTP(S)   │   │     SMB     │ ...
└─────────────┘   └─────────────┘   └─────────────┘
```

两种寻址方式决定流量去向:

- **主机名前缀**——用于 HTTP(S) 服务。服务端读取 `Host` 头(如 `myapp.relay.example.com`),按第一个 `.` 前的前缀路由。默认用客户端的 `id` 作为前缀,`-id myapp` 即发布 `myapp.<中转域名>`。
- **TCP 端口**——用于一切 TCP 服务(SSH、SMB、数据库、游戏服务器等)。服务端开启端口并直通转发给客户端的本地服务。

P2P 模式下中转只负责撮合连接,数据随后经 WebRTC 在两端之间直达。参见 [P2P 直连](examples.md#p2p-直连)。

## 核心概念

| 概念 | 说明 |
|------|------|
| GT Server | 中转端。需要一台有公网 IP 的机器(VPS/云主机),或直接使用 [console.gtunnel.dev](https://console.gtunnel.dev) 的托管中转 |
| GT Client | 部署在内网服务旁边,主动拨出连接中转。在 NAT 后无需任何端口映射 |
| id / secret | 客户端凭证,id 同时充当主机名前缀 |
| Web 管理台 | `gt server` / `gt client` 不带参数启动,即可在浏览器里编辑配置,不用写 YAML |
| GT-Desktop | 同一引擎的图形界面封装,见[主页](/zh/) |
